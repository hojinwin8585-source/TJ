# 종이마을 통합판(코덱스 제작) 검토와 합치는 계획

보내 주신 화면 5장을 보고 검토했습니다. 파일 자체(html 125MB, zip 91MB)는 크기 제한 때문에 열지 못했으므로 **화면에 보이는 것만** 근거로 했습니다. 직업 옷 입히기, 길 찾기 미로의 실제 화면은 아직 못 봤습니다.

## 1. 좋은 점 (살릴 것)
- **놀이 마을 그림**: 종이 공예 원 4개(요리 마을, 꾸미기 살롱, 배움 학교, 노래 극장)와 가운데 집(내 방). 차분하고 입체감이 있음. 그대로 홈의 중심으로.
- **실사진 낱말 카드**: 큰 사진, 한글과 영어 낱말, 소리. 아이가 진짜 모습을 배움. 더 키울 가치가 큼.
- 토토가 서 있는 오늘의 놀이 배너의 분위기, 차분한 바탕색.

## 2. 고칠 점
| 화면 | 문제 | 어긴 규칙 (`config.json`의 `rules`) |
|---|---|---|
| 홈 | 세로로 3화면 길이. 들어가는 방식이 6가지(오늘의 놀이, 놀이 목록, 실사진 카드 줄, 놀이 마을, 바로 놀기, 탐험대)라 뒤죽박죽. 요리 마을이 두 군데 | `sameLayoutEverywhere` |
| 홈 | '리듬 박수', '시작하기', '0 / 3 완료', '버거부터 이탈리아까지' 등 글자를 읽어야 함 | `noReading` |
| 홈 | 바로 놀기 카드가 이모지(🍔 🐰 🎄)와 작은 글자 | `noReading`, 이모지 금지 |
| 홈 | 탐험대가 가로로 넘기는 방식(작은 화살표) | `bigAndFew` |
| 실사진 카드 | 묶음 고르기가 글자 목록, 한 묶음 109장, '26 / 109' 숫자 | `noReading`, `bigAndFew` |
| 실사진 카드 | '다시 듣기' 글자 버튼, 작은 화살표 | `noReading` |
| 실사진 카드 | 아이 화면에 '사진 출처' 링크(앱 밖으로 나감) | 안전 |
| 실사진 카드 | 2살에게 맞지 않는 사진(뼈 표본) | `photoCards.curation.exclude` |
| 파일 | 사진을 html 안에 넣어 125MB. 휴대폰에서 느리고, 고치기도 어려움 | `merge.noSingleHugeHtml` |

## 3. 합치는 계획
앱이 두 갈래입니다: **이 저장소**(규칙·검사, 미용실, 네일숍, 목소리, 살아 있는 캐릭터)와 **통합판**(놀이 마을 홈, 실사진 카드, 셰프 도전, 미로, 크리스마스 집, 리듬 박수, 직업 옷). 따로 두면 고친 것이 서로 반영되지 않습니다.
- **저장소를 유일한 기준으로** 합니다(`merge.base`). 검사와 규칙이 여기 있기 때문입니다.
- 순서: ① 코덱스가 통합판 원본을 저장소에 올림(아래 요청문) → ② `P0.md`로 합침 → ③ 옮겨 온 화면을 `P13`~`P15`, `P8`, `P9`에서 규칙에 맞게 다듬음.

### 코덱스에게 보낼 요청문 (복사해서 쓰세요)
```
지금 만든 '말랑놀이터 종이마을 통합판'의 원본을 GitHub 저장소 hojinwin8585-source/TJ 에 올려 주세요.
- 새 브랜치 codex-paper-village 를 만들고, 폴더 '종이마을/' 아래에 올립니다. 다른 폴더는 건드리지 않습니다.
- html 한 파일에 사진을 넣지 말고, 사진은 '종이마을/photos/<묶음>/<이름>.webp' 파일로 따로 저장합니다(긴 변 800px, 한 장 80KB 이하).
- 사진 목록은 '종이마을/photos/cards.json' 에: id, ko, en, file, set(묶음), credit(출처), license.
- 화면별 코드는 파일을 나눠서(홈, 실사진 카드, 셰프 도전, 미로, 크리스마스 집, 리듬 박수, 직업 옷 입히기).
- '종이마을/README.md' 에 화면 목록, 파일 구조, 저장하는 데이터(localStorage 키)를 적어 주세요.
- 파일 하나가 50MB를 넘지 않게 합니다.
```

## 5. 추가 검토: 놀이 화면 29장 (두 번째로 보내 주신 캡처)

한 줄 결론: **"많이 단순하다"가 맞습니다.** 놀이가 30개쯤 있지만 대부분 한 가지 동작을 몇 번 하면 끝나고, 그림은 이모지이고, 화면 틀이 제각각입니다. 이 중 절반은 제가 처음에 만든 놀이가 그대로 남은 것입니다(소리 놀이, 젤리 세기, 아이스크림, 출동 놀이, 짝 맞추기, 직업 옷, 공주 왕자 옷, 손톱 꾸미기, 그림 그리기, 집안일, 설거지). 통합판에는 그 뒤에 고친 미용실·네일숍·목소리가 들어 있지 않습니다(예전 손톱 꾸미기가 그대로 있음).

### 화면별
| 화면 | 보이는 문제 | 어떻게 |
|---|---|---|
| 소리 놀이 | 이모지 12칸 넘게, 세로로 밀기 | 실사진 '소리 카드' 3장씩 (`photoCards.soundCards`) |
| 노래 극장 | 타일 2개뿐, 이모지 | 장소 화면 틀로, 놀이 3개 |
| 크리스마스 집 | **방 그림은 좋음.** 글자 탭 4개와 글자 안내 | 그림은 살리고 탭·글 삭제 (`games.xmasHouse`) |
| 미로 찾기 | 단계 탭, 글 안내, 점무늬 배경, 누를 점이 작음, 막다른 길 | 칸 방식은 살리고 발자국 110px (`games.maze`) |
| 바삭 치킨, 호텔 아침 식사 | 둘 중 고르기 + '다음 →' 글자 버튼. 요리 동작 없음 | 진짜 요리로 (`games.restaurant`) |
| 홈 아래(바로 놀기, 탐험대) | 이모지 카드, 가로 넘김, '도장 3개에 열려요' | 장소 안으로, 글자 자물쇠 삭제 |
| 파도 바다 | 이모지 3장(약 80px), 글자 버튼 '낱말 카드'·'물안경 잠김' | 실사진 '어디 있지?' 방식 |
| 실사진 카드 | '몸·건강' 묶음에 나뭇잎: **분류가 틀림** | 전체 다시 분류 (`rules.dataMakesSense`) |
| 그림 그리기 | 빈 종이, 위에 이모지 버튼 3개, 색 8개가 가로로 밀림 | 색칠과 합쳐 밑그림 고르기부터 |
| 리듬 박수 | 북 그림을 누르면 소리만. 아래 칸 비어 있음 | 토토의 작은 음악회 (`games.rhythmClap`) |
| 젤리 세기 | 화면 대부분이 비어 있음, 1~5·1~10 글자 전환 | 틀에 맞추고 단계는 자동 |
| 아이스크림 가게 | 이모지 펭귄, 세모·네모 도형, 빈 화면 | 스쿱으로 뜨는 진짜 가게 (`games.icecream`) |
| 출동 놀이 | 키워서 흐려진 이모지 집과 불 | 직업 놀이의 '일 해 보기'로 |
| 짝 맞추기 | 끌어야만 됨, **짝이 틀림**(조종사와 버스) | 직업 놀이의 '탈것 고르기'로 |
| 직업 옷 입기 | 노란 이모지 얼굴 + 세모 몸, 직업 줄이 가로로 밀림, 누르면 한 번에 바뀜 | 직업 놀이 (`games.jobs`, P15) |
| 공주 왕자 옷 입기 | 같은 세모 인형, 글자 탭 6개, 얼굴 줄이 가로로 밀림 | 옷 가게 (`games.clothes`) |
| 손톱 꾸미기 | 예전 것 | 네일숍으로 대체(이미 만듦) |
| 집안일 하기 | 이모지 장난감 6개를 상자에 넣으면 끝, 이모지 탭 4개 | 과정이 있는 집안일 4가지 (`games.chores`) |
| 설거지 하기 | 문지르기와 수도꼭지 누르기뿐, 아래 칸 비어 있음 | 7과정 설거지 (`games.dishes`) |

### 왜 단순하게 느껴지나 (공통 원인 5가지)
1. **깊이가 없음**: 한 가지 동작 몇 번이면 끝. 과정이 이어지지 않고, 누구를 위해 하는지 없고, 결과물이 남지 않음 → `rules.depth`
2. **이모지 그림**: 29장 중 20장 넘게 이모지. 키우면 흐리고 그림체가 섞임 → `rules.noEmojiArt`
3. **틀이 제각각**: 머리줄, 버튼 자리, 글꼴, 전환 버튼이 화면마다 다름 → `shell`, `rules.oneShell`
4. **글자 의존**: 안내 줄, 탭, '다음' 버튼, 자물쇠 설명 → `rules.noReading`
5. **빈 화면과 작은 캐릭터**, 살아 있지 않음 → `rules.noDeadSpace`, `calm.characterLife`

### 방향: 적게, 깊게
놀이 수를 줄이고(비슷한 것은 합침: `catalog.retired`), 남기는 놀이는 미용실·네일숍 수준으로 깊게 만듭니다. 최종 목록은 `config.json`의 `catalog`.
