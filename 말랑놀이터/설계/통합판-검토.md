# 종이마을 통합판(코덱스 제작) 검토와 합치는 계획

보내 주신 화면 5장을 보고 검토했습니다. 파일 자체(html 125MB, zip 91MB)는 크기 제한 때문에 열지 못했으므로 **화면에 보이는 것만** 근거로 했습니다. 직업 옷 입히기, 길 찾기 미로의 실제 화면은 아직 못 봤습니다.

## 1. 좋은 점 (살릴 것)
- **놀이 마을 그림**: 종이 공예 원 4개(요리 마을, 꾸미기 살롱, 배움 학교, 노래 극장)와 가운데 집(내 방). 차분하고 입체감이 있음. 그대로 홈의 중심으로.
- **실사진 낱말 카드**: 큰 사진, 한글과 영어 낱말, 소리. 아이가 진짜 모습을 배움. 더 키울 가치가 큼.
- 토토가 서 있는 오늘의 놀이 배너의 분위기, 차분한 바탕색.

## 2. 고칠 점
| 화면 | 문제 | 어긴 규칙 (`config.json`의 `rules`) |
|---|---|---|
| 홈 | 세로로 3화면 길이. 들어가는 방식이 6가지(오늘의 놀이, 놀이 목록, 실사진 카드 줄, 놀이 마을, 바로 놀기, 탐험대)라 뒤죽박죽. 요리 마을이 두 군데 | `sameLayoutEverywhere` |
| 홈 | '리듬 박수', '시작하기', '0 / 3 완료', '버거부터 이탈리아까지' 등 글자를 읽어야 함 | `noReading` |
| 홈 | 바로 놀기 카드가 이모지(🍔 🐰 🎄)와 작은 글자 | `noReading`, 이모지 금지 |
| 홈 | 탐험대가 가로로 넘기는 방식(작은 화살표) | `bigAndFew` |
| 실사진 카드 | 묶음 고르기가 글자 목록, 한 묶음 109장, '26 / 109' 숫자 | `noReading`, `bigAndFew` |
| 실사진 카드 | '다시 듣기' 글자 버튼, 작은 화살표 | `noReading` |
| 실사진 카드 | 아이 화면에 '사진 출처' 링크(앱 밖으로 나감) | 안전 |
| 실사진 카드 | 2살에게 맞지 않는 사진(뼈 표본) | `photoCards.curation.exclude` |
| 파일 | 사진을 html 안에 넣어 125MB. 휴대폰에서 느리고, 고치기도 어려움 | `merge.noSingleHugeHtml` |

## 3. 합치는 계획
앱이 두 갈래입니다: **이 저장소**(규칙·검사, 미용실, 네일숍, 목소리, 살아 있는 캐릭터)와 **통합판**(놀이 마을 홈, 실사진 카드, 셰프 도전, 미로, 크리스마스 집, 리듬 박수, 직업 옷). 따로 두면 고친 것이 서로 반영되지 않습니다.
- **저장소를 유일한 기준으로** 합니다(`merge.base`). 검사와 규칙이 여기 있기 때문입니다.
- 순서: ① 코덱스가 통합판 원본을 저장소에 올림(아래 요청문) → ② `P0.md`로 합침 → ③ 옮겨 온 화면을 `P13`~`P15`, `P8`, `P9`에서 규칙에 맞게 다듬음.

### 코덱스에게 보낼 요청문 (복사해서 쓰세요)
```
지금 만든 '말랑놀이터 종이마을 통합판'의 원본을 GitHub 저장소 hojinwin8585-source/TJ 에 올려 주세요.
- 새 브랜치 codex-paper-village 를 만들고, 폴더 '종이마을/' 아래에 올립니다. 다른 폴더는 건드리지 않습니다.
- html 한 파일에 사진을 넣지 말고, 사진은 '종이마을/photos/<묶음>/<이름>.webp' 파일로 따로 저장합니다(긴 변 800px, 한 장 80KB 이하).
- 사진 목록은 '종이마을/photos/cards.json' 에: id, ko, en, file, set(묶음), credit(출처), license.
- 화면별 코드는 파일을 나눠서(홈, 실사진 카드, 셰프 도전, 미로, 크리스마스 집, 리듬 박수, 직업 옷 입히기).
- '종이마을/README.md' 에 화면 목록, 파일 구조, 저장하는 데이터(localStorage 키)를 적어 주세요.
- 파일 하나가 50MB를 넘지 않게 합니다.
```
